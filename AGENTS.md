# agent-harness — Agent Operating Rules

OpenCode V2 loads this file as always-on instructions (V1 `instructions` is ignored). Expanded rules: [`.agents/rules/00-operating.md`](.agents/rules/00-operating.md); rulebook: [`.agents/rulebook.md`](.agents/rulebook.md). Read both before non-trivial work.

It governs: Step Zero subagent dispatch, zero-speculation debugging, data integrity, UI/RTL ergonomics, stack-version discipline, token efficiency, right-sized QA tiers, and the commit-and-push gate.

- **Dispatch** by tier T0–T3 (`dispatch_persona`/`subagent`; `.agents/rules/00-operating.md` §Step Zero); see `.agents/skills/<persona>/SKILL.md`.
- **Todo list discipline**: for multi-step work keep opencode's right-hand todo panel current with the `todowrite` tool — create it before the second/third step, exactly ONE item `in_progress`, mark each item `completed` immediately after its own verification step, and close every finished item before you checkpoint/report. A single-step/single-file fix needs no list; a panel that lags the work is worse than none. The context-guard nudges "create / sync / close" mechanically when it falls behind.
- **Features**: capture a found item as one light row on the canonical board (the shared board service, ADR 0001) — `features` is a registrar only. Update the board with the `backlog_*` tools (or `node scripts/backlog.js`); never hand-edit a board file. The board is **project-scoped**: a write from a feature worktree lands on the shared service or main board, never a worktree copy. When a feature is picked up, author the per-feature doc chain (intent/scope/plan/tests) by dispatching each author persona **directly** (`product-manager` → intent, `system-architect` → scope, `planner` → plan, `qa-architect` → tests) — never via `features`. For an "investigate + plan" request, dispatch `planner` / `product-manager` directly.
- **Provider funds stop**: a provider funds/quota error (`insufficient balance`/`funds`/`credits`, usage limit, 402) pauses the session — announce the failed provider/model and the exact unfinished step, checkpoint, and wait for the user's explicit top-up-complete message; never retry, degrade inline, or silently skip. Model priority is OpenCode Go (`opencode-go/*`) first, DeepSeek direct (`deepseek/*`) fallback — the V4 Pro architect tier (`planner`/`qa-architect`/`system-architect`/`security-engineer`) pins `opencode-go/deepseek-v4-pro#high`, with direct `deepseek/deepseek-v4-pro` as the announced fallback — announce every fallback immediately.
- **Product-first planning**: planning is value-led, not tech-led — define the user (actor/need/outcome/acceptance) before code, sequence work value-first against `.agents/memory/product-principles.md`, and let `npm run test:product` enforce it.
- **Report value-first, at the reader's level**: completion reports open with what value shipped (plain language — what the user now gets, why it matters) + the main "how", before any file/test/commit detail. Write for someone who knows the product, not the code: lead with behavior in plain terms and use a code identifier only when precision needs it (glossed on first use); stay concrete and technical, never abstract.
- **Docs**: human-facing docs (`README.md`, `CHANGELOG.md`, `docs/**`) are owned by the `docs` persona — docs point at code, never duplicate it, and `npm run test:docs` enforces no placeholders / no dangling links / well-formed ADRs / every shipped commit has a changelog entry.
- **Always-loaded budget (`test:prefix`)**: this file is billed on every request, so a byte ceiling guards it and the gate runs in the ship/pre-push battery. If it trips, first tighten the wording — keep the rule, cut repetition; if the content is genuinely needed, ask the user to approve more room, then raise the deliberate ceiling in `scripts/qa/check-prefix-stability.js` (template + deployed copy) with a changelog note. Never delete a rule just to fit, and never bypass the gate.
- **Finalize with one call**: `npm run finalize -- --feature <id>` archives, commits, integrates on `origin/main`, gates, lands by **direct fast-forward push to `main`**, then waits (bounded) for **CI green on the landed SHA**. Invoke it once and let it finish — **do NOT checkpoint-and-stop**; a red CI is a blocker to record. Details: `.agents/rules/00-operating.md` §Commit & push; `agent-harness doctor --target .` reports readiness.
- **Every change touching code paths gets a QA plan** (a per-change file under `.agents/qa-plans/`) from `qa-architect` — if it isn't dispatched, the main orchestrator plans in its place. `npm run test:qa-plan` fails on any changed code path with no covering assertion or waiver, and on any touched flow (`.agents/memory/flow-map.md`) whose sibling surfaces / declared variants the plan doesn't address. The plan also carries the test-design record (`## Test budget`, `## Oracle & owner`, `## Test-design self-check`); `npm run test:wiring` fails orphaned tests and the linger check flags passing-but-idling suites (T1–T10 → `.agents/memory/test-design-parameters.md`).
- **Declared bugs start with a diagnosis** (`/diagnose`): `kind: bug|incident|fix` work needs `diagnosis.md` — ≥2 candidates with discriminating tests, ruled-out causes, falsification, and a red→green oracle; `npm run test:diagnosis` enforces it. Details: `docs/harness-lifecycle.md`.
- **Three environments**: `development` (dirty by design), `uat` and `production` (enforced clean). Only code + schema migrations + idempotent seeds move forward; data never crosses the boundary. Finalizing lands on `main`, CI deploys the SHA to **uat**, then `test:data-hygiene -- --env uat`; production is human-gated. Details: `.agents/memory/environments.md`.
- **At session start**, run `node scripts/orient.js` (the `orient` tool) — one call returning the tree/branch/HEAD/dirty, active feature, checkpoint, board rows, owned files, live serve jobs + capacity, last device-run summary, **and a bounded digest of the session-start memory files** (`locations.md`, `model-routing.md`, `orchestration.md` budgets, `product-principles.md`, `environments.md`, `dev-loop.md` — each digest carries the file's `##` section index and its first table). Use that digest; open a memory file (or `Grep` a section) only when a specific fact is not in it. The board lives in the shared board service (see `node scripts/backlog.js list` / the `backlog_list` tool; ADR 0001). For review work, read `.agents/memory/quality-parameters.md` (the P1–P8 rubric) and write deliverables under `.agents/reviews/<id>/` (never `.agents/features/`).
- **Run/verify via the `dev-loop` skill**: before running a test tier, a single test, a seed/reset, the emulator, or the dev server, load the `dev-loop` skill (`skill` tool → `dev-loop`) and read `.agents/memory/dev-loop.md` (project-owned concrete commands). It carries the tier map, the single-test invocation, the `serve.js` start/stop/run lifecycle, `gates`/`where`, and "read the failing gate, don't re-run it blind". Bound an `explore` dispatch with the `bounded-explore` skill (paths + one question + file:line budget) — it is the most expensive dispatch otherwise.
- **Prefer the harness tools over the shell**: `gates --phase=quick` runs a tier with bounded output, `where <term>` finds a symbol, `orient` re-orients — use them instead of `npm run … | tail` or shell `grep`/`find`/`cat`/`ls` (the dedicated `Read`/`Glob`/`Grep` tools are capped and ignore-aware).
- **MCP is per-agent and dev-only**: every MCP tool schema is billed on every request, and opencode spawns MCP servers outside the `serve.js` capacity envelope. The managed `mcp.use: "*"` policy default-denies MCP; append a per-server allow, then deny its tools globally (a `<server>_*` rule in `permissions`) and re-enable only for the persona that needs live external state. Point any DB server at **development** only; do not enable GitHub MCP. Details: `docs/mcp-integrations.md`.
- **Bounded orchestration**: one bounded context per work unit — checkpoint into the session's `.agents/handoffs/<feature-id>.md` when approaching the budgets in `.agents/memory/orchestration.md`, and prefer a fresh context that resumes from the checkpoint over unbounded transcript growth.
- **Ignore-aware search**: never `rg --no-ignore`/`-u` (it walks `node_modules`/build trees and floods time + context). Use `npm run search -- <pattern>` (`scripts/agent-search.sh`, honours the canonical `.ignore`, capped, `--files` for cheap discovery) for content search, and `git grep -n <symbol>` for tracked-symbol searches (tracked files only, reads the index). Details: `docs/wsl-optimizations.md`.
- **RAM-backed caches**: `npm run ramdisk` mounts a volatile tmpfs cache for build/cache env vars only — never source or git state. Details: `docs/wsl-optimizations.md`.
- **Machine capacity guardrail**: parallel sessions are fine, parallel **heavy tiers** are not (one WSL2 VM). Launch long-lived processes through `node scripts/serve.js` (capacity + machine-wide heavy lock, capped by default) and heavy one-shots via `serve.js run --cmd "<cmd>"`; stop servers/emulator at session end. One-time VM/GPU tuning: `scripts/wsl-tune.sh apply` / `scripts/wsl-gpu.sh apply`. Envelope: `.agents/memory/orchestration.md`; details: `docs/wsl-optimizations.md`.
- **Session telemetry**: at wrap-up record the `session_info` line plus `work_type` / `outcome` / `termination_reason` in the handoff's `## Session metadata`; `npm run report -- --cost --since=14d` joins it to the feature.

> Deployed and maintained by `opencode-agent-harness` (`npx opencode-agent-harness init` / `update`). Harness-owned files (`scripts/qa/**`, `scripts/*.js`, `.opencode/**`, `.agents/skills/**`, `.agents/rules/**`, `.agents/rulebook.md`, `AGENTS.md`, opencode config) must be fixed **upstream in the harness `templates/`**, not hand-edited here — `update` fails closed on a hand-edit and points at `templates/`; `--accept-harness` overwrites deliberately after a backup.
